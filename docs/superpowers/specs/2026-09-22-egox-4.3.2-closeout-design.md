# EgoX 4.3.2 阶段性收口设计

## 目标

以已经完成真机测试的 EgoX 4.3.1 为行为基线，完成一次不增加功能的阶段性收口：

- 将仍在生效或面向用户的 NekoBox、Asteria 品牌标识统一为 EgoX。
- 修复通过复现、测试或构建检查确认的正确性问题。
- 在仅支持 Android 16（API 36）和 arm64-v8a 的产品边界内，删除已证明无用的兼容与品牌遗留。
- 交付版本为 EgoX 4.3.2。

本次工作不继续推进新功能、界面改版或未经证据支持的性能调整。

## 已确认基线

- Git 基线：`main` 分支的 EgoX 4.3.1。
- 应用包名：`com.egox`。
- Android 范围：`minSdk=36`、`targetSdk=36`、`compileSdk=36`。
- CPU 范围：仅 `arm64-v8a`。
- EgoX 4.3.1 已由用户完成真机测试。
- 当前 Kotlin/Java 内部命名空间包含 `io.nekohasekai.sagernet` 与 `moe.matsuri.nb4a`。

## 身份与兼容边界

### 必须统一为 EgoX

- 应用名称、长名称、快捷设置名称和其他用户可见品牌文本。
- 崩溃报告标题、日志分享标题以及新建备份的默认文件名。
- 当前构建使用的版本配置、CI 路径过滤和发布产物名称。
- 已经不承担兼容职责的 Asteria 资源名、脚本文本和开发工具文本。
- 当前项目自己的说明文案；上游来源说明除外。

### 必须保留

- `com.egox` 应用包名及其覆盖安装、应用数据和签名连续性。
- 数据库名称、Room schema、偏好键、备份字段、Parcelable/Kryo 结构及 Router 稳定标识。
- `io.nekohasekai.sagernet`、`moe.matsuri.nb4a` 等内部命名空间。
- 插件发现、Intent action、authority 或其他外部兼容接口中具有协议意义的旧标识。
- README、LICENSE 和 AUTHORS 中必要的 NekoBox、SagerNet、Matsuri 等上游署名与历史来源。

内部命名空间和兼容接口不属于对外品牌。仅为了视觉上的“全部同名”而迁移它们，会增加数据库、Manifest、序列化、插件和升级兼容风险，因此不在本次范围内。

## 名称收口

构建元数据以 `egox.properties` 为唯一版本来源。完成相应构建和 CI 验证后，删除 `asteria.properties` 及其构建回退逻辑。签名文件不按文件名盲目删除；必须先确认实际发布签名来源和 4.3.1 证书连续性。

所有 locale 中覆盖 `app_name`、`app_name_long` 或 EgoX 快捷设置名称的资源必须统一。未被引用的 Asteria 图标资源可以删除，但只有资源引用审计和构建均证明其无用时才能执行。

备份文件名只影响新导出的默认名称，改为 `egox_backup_<timestamp>.json`。备份内容格式与旧 Asteria/EgoX 备份的导入能力保持不变。

README 的当前版本更新为 4.3.2，并明确 EgoX 是基于 NekoBox for Android 演进的个人分支；不得删除上游链接、许可证说明或贡献者归属。

## Bug 收口方法

Bug 修复遵循逐项 RED→GREEN：

1. 收集可重复的失败、错误日志或静态不一致证据。
2. 为该问题建立最小自动化回归测试；无法单元测试的构建或 APK 问题使用确定性验证任务。
3. 运行测试并确认它因目标问题失败。
4. 只实施修复根因所需的最小改动。
5. 运行目标测试和完整相关测试集，确认问题消失且没有回归。

首个已确认问题是 `app/src/main/res/xml/shortcuts.xml` 中的四个静态快捷方式仍指向 `com.asteria`，而实际应用包名是 `com.egox`。这会使快捷方式定位错误包。修复应让快捷方式目标与构建包名一致，并加入防回归检查。

统一审计覆盖：

- Manifest、静态快捷方式和 Android 组件目标。
- VPN 启动与前台服务生命周期。
- Router 选择、URL Test、订阅解析与刷新。
- 备份导入导出和已有数据兼容。
- Debug/Release 构建、签名、版本和 APK 内容。

审计只修复可以证明的缺陷。没有复现、失败测试或清晰静态契约证据的问题不进行猜测性修改。

## 精简原则

项目产品范围固定为 Android 16 / API 36 与 arm64-v8a。精简候选包括：

- 已被 EgoX 配置替代的 Asteria 构建回退。
- 已证明无引用的旧品牌资源和开发预览文本。
- 仍会生成或校验非 arm64 ABI 的项目自有构建入口。
- 仅服务于 API 35 及以下、且在 API 36 上没有兼容或行为意义的项目自有代码。

以下内容默认不删：

- 协议实现、Router、订阅、URL Test、备份、请求观察器及其他现有功能。
- 数据迁移、旧备份导入、序列化兼容和插件兼容代码。
- AndroidX 或第三方库内部的兼容实现。
- 不能通过测试、引用分析和构建共同证明无用的代码。

精简不是按关键词批量删除。每一项删除都必须能说明其引用状态、兼容影响和验证方式。

## 版本与发布

- `VERSION_NAME=4.3.2`。
- `PRE_VERSION_NAME=pre-4.3.2`。
- 原始 `VERSION_CODE` 从 60 单调递增到 61；按现有构建规则，APK `versionCode` 应为 305。
- Release APK 名称应包含 `EgoX-4.3.2-arm64-v8a`。
- 保持与 4.3.1 相同的包名和签名证书，以支持覆盖安装和保留应用数据。

## 验证与验收

### 基线

修改前运行并记录：

- `:app:testOssDebugUnitTest`
- `:app:compileOssDebugAndroidTestKotlin`
- `:app:lintOssDebug`
- `:app:verifyLibcore`
- `:app:verifyOssDebugLibcoreCallers`
- `:app:assembleOssDebug`
- `:app:testOssReleaseUnitTest`
- `:app:assembleOssRelease`

如果基线已有失败，先判断是环境、既有缺陷还是当前收口范围内的问题，不通过删除测试或降低检查级别获得绿色结果。

### 最终主机验收

- 完整相关测试通过，lint 的错误数为零；警告按类别如实报告。
- Debug 与 Release APK 构建成功。
- `aapt` 确认包名 `com.egox`、版本名 4.3.2、versionCode 305、min/target SDK 36。
- APK 只包含 arm64-v8a 原生库。
- `apksigner` 确认签名有效，并与 4.3.1 发布 APK 证书一致。
- APK 资源检查确认所有 locale 显示 EgoX，静态快捷方式指向实际包名。
- 全仓品牌扫描不再发现不应存在的 Asteria 生效标识；允许项必须属于历史证据、上游署名或兼容契约。
- Git diff 只包含本设计直接要求的改动。

### 真机边界

EgoX 4.3.1 的既有真机测试是本次行为基线，但不能自动证明 4.3.2。若本轮没有在设备上重新安装并验证，交付结论必须明确写为“主机验证完成，4.3.2 真机验收未执行”。

建议的 4.3.2 真机烟雾测试为：覆盖安装、既有数据仍在、VPN 启停、Router 切换、URL Test、订阅刷新、备份导出导入和四个静态快捷方式。

## 明确不做

- 不新增协议、策略组、UI 页面、自动化功能或配置项。
- 不重新设计 VPN、Router、URL Test、订阅或通知行为。
- 不迁移内部 Java/Kotlin 命名空间。
- 不更改应用包名、数据库身份、备份结构或签名身份。
- 不为了减少代码量而删除当前功能。
- 不提交凭据、密钥内容或私有配置。
- 不推送远端或发布 GitHub Release，除非用户另行明确要求。
